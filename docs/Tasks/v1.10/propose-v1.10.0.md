# Propose v1.10 · 申請表單欄位下拉化(降低人工配對落空)

> 此為 **proposal**(規劃草案),確認後即轉為正式 `tasks-v1.10.0.md`。
>
> 對應母本:[v1.9.1 申請單生命週期 + 規則路由 + AI 欄位驗證自動開通](../v1.9/propose-v1.9.1.md)。

## 1. 目標

延續 v1.9.x 的「規則路由自動開通」,從**表單輸入端**降低申請被打回人工的機率:把容易打錯、與既有資料對不上的欄位改為**下拉選取(Combobox)**,讓送出的值天生與系統主檔一致。

## 2. 範圍

### 2.1 專案負責人改為 Combobox(已實作於 `dev-v1.10`)

- 「專案負責人」由純文字輸入改為 **Combobox**,清單來源為**現有平台 member**(SSO 首登自動建立,`username` = M365 顯示名、`email` = M365 信箱)。
- 選取負責人後**自動帶入信箱**,信箱欄位設為唯讀,避免名稱與 M365 資訊對不起來。
- 後端新增 `GET /api/v1/users/owner-options`(任何登入者可用,回傳 `username` + `email`,排除系統管理員 `account='admin'`)。

### 2.2(承先)部門已為 Combobox

- 部門早於 v1.9.x 即為 Combobox,代號自動帶入且唯讀;`department_code` 是規則路由的配對鍵(查無/名稱不符即落人工),非裝飾欄位。

## 3. 待確認 / 後續候選

- 負責人清單目前僅含「登入過本平台」的 member;若需含未登入者的完整 M365 目錄,須另接 Graph `User.Read.All`(本版不做)。
- 其他可下拉化的表單欄位待盤點。
