使用者使用說明

SDK 使用者透過 SDK Key + User Token + Project Code 呼叫代理端點的完整說明

目錄 概述 取得憑證 端點與 Header Request Body 多輪對話與生成參數 Response 格式 完整範例 串流回應(SSE) 錯誤碼對照 查看部門用量 安全注意事項

概述

本平台為 OpenRouter API 的代理層:統一管理金鑰、模型白名單與用量稽核。使用者不需要登入此網站,只需要拿到管理員發放的三組憑證,即可在自己的程式碼或工具裡呼叫代理端點。

管理員(admin)透過本網站集中發放與管理憑證、模型白名單與部門金鑰;成員(user)只接觸下面提到的「SDK Key + User Token + Project Code」三因子組合。

取得憑證(由管理員發放)

呼叫代理端點需要三組憑證,皆由管理員在後台建立後給予使用者:

X-SDK-Key

部門層級 · 存取金鑰

以部門為單位發放,代表「哪個部門的程式在呼叫」。由 admin 於後台「存取金鑰 / SDK Keys」建立,格式類似 ordsk_xxxxxxxxxxxx_xxxx…。

X-User-Token

使用者層級 · 加密 payload

以個別使用者為單位發放,代表「哪個人在呼叫」。由 admin 於「使用者管理」頁針對 role=user 的使用者產生,為加密字串、內含使用者識別與發行時間。

X-Project-Code

專案層級 · 代碼

以部門下的專案為單位發放,代表「這次呼叫歸到哪個專案算用量」。值為「專案管理」頁顯示的 代碼 欄(系統自動產生的數字字串)。同把 SDK Key 可呼叫同部門任一專案。

⚠ SDK Key 與 User Token 只在建立時顯示一次。請妥善保管,遺失只能請管理員重新發放(同時舊憑證會被撤銷)。

⚠ 三者必須屬於同一部門(SDK Key / User Token 綁部門;Project 屬部門),否則代理端會回 401 unauthorized 或 400 project_invalid。

端點與認證 Header

本平台提供測試與正式兩個環境,請依用途選用對應的 Base URL;以下範例皆以正式環境為準。

環境Base URL
測試環境https://df-it-openrouter-dispatch-stage-api.it.zerozero.tw
正式環境https://df-it-openrouter-dispatch-api.it.zerozero.tw

所有呼叫皆透過下面這支端點:

HTTP
POST https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/model/chat
Content-Type: application/json
X-SDK-Key: <SDK Key 明文>
X-User-Token: <User Token 明文>
X-Project-Code: <專案代碼>
  • 三個 Header 皆必填;缺 SDK Key / User Token 回 401 unauthorized,缺 X-Project-Code 回 400 project_code_required,Project 不屬該部門 / 已停用 回 400 project_invalid。
  • 請勿把憑證寫死於前端 / 公開 repo / 客戶端 App;只能存放在受控的後端或 CI Secret 環境變數。

Request Body

JSON body 欄位如下:

欄位型別必填說明
modelstring是OpenRouter 模型 id(例:google/gemini-2.5-flash),須在管理員設定的白名單內
textstring否使用者輸入的文字
imagesstring[]否圖片 URL 或 data:image/...;base64,... 字串陣列
filesobject[]否上傳檔案(如 PDF),每筆為 { "filename": "報表.pdf", "file_data": "..." };file_data 可為 data:application/pdf;base64,... 或可公開存取的遠端 URL。僅檔名會寫入用量紀錄,檔案內容不留存(法務考量),且是否支援讀取取決於該模型本身的多模態能力
videosstring[]否暫不支援,送出即回 400 feature_not_supported
toolsobject[]否工具清單,格式同 OpenAI tools 規格,原樣轉發給下游。目前僅支援 OpenRouter server 端內建工具(如 web search,見下方範例);會回 tool_calls 的 function calling 尚未開放。單輪與 messages 兩種模式皆可搭配
messagesobject[]否多輪對話模式:OpenAI 風格 { role, content } 訊息陣列(system prompt / 對話歷史)。與 text / images / files 擇一使用,同時帶回 400。詳見多輪對話與生成參數
temperaturenumber否取樣隨機性,0–2;越低越穩定、越高越發散。未帶則用模型預設值
max_tokensinteger否回覆長度上限(token 數),≥ 1;未帶則用模型預設值
response_formatobject否結構化輸出:{"type":"json_object"}(回覆保證為合法 JSON)或 {"type":"json_schema","json_schema":{...}}(指定 schema)。未帶則為一般文字回覆

可用的 model 清單由管理員集中維護。你可隨時查詢已啟用的模型清單(見下方查詢可用模型清單),從中複製 model_key 填入此欄位;若呼叫時收到 403 model_forbidden,請向管理員確認該模型是否已啟用。

GET查詢可用模型清單

以 GET 取得目前已啟用的完整模型清單:

HTTP
GET https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/allowed/models
  • 此端點不需任何憑證,可直接於瀏覽器開啟:https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/allowed/models
  • 回應 data[](陣列)每筆的 model_key 即為呼叫上方端點時 model 欄位要填入的值;provider(來源,如 openrouter)、name 為顯示名稱、description / context_length / modality / input_modalities / output_modalities 供參考(modality tag 為陣列,例 ["text","image"])。
  • 僅回傳已啟用(白名單內)的模型;定價、tokenizer 等內部欄位不對外。

JSON
{
  "model": "google/gemini-2.5-flash",

  "images": [

含檔案(PDF)的 Request 範例:

JSON
{
  "model": "google/gemini-2.5-flash",
  "text": "請摘要這份 PDF 的重點",
  "files": [
    {
      "filename": "季報.pdf",
      "file_data": "data:application/pdf;base64,JVBERi0xLjcKJ..."
    }
  ]
}
  • file_data 可改用可公開存取的遠端 URL(如 https://example.com/季報.pdf)。
  • 能否實際讀取 PDF 取決於所選模型的多模態能力;不支援的模型可能忽略檔案或由 OpenRouter 回對應錯誤。
  • 基於法務考量,僅檔名會寫入用量紀錄,檔案內容只用於本次請求、不留存。

啟用 web search 的 Request 範例:

JSON
{
  "model": "google/gemini-2.5-flash",
  "text": "今天台積電(2330)的最新股價與相關新聞?",
  "tools": [{ "type": "openrouter:web_search" }]
}
  • 帶 tools 即可啟用 OpenRouter server 端內建工具;web search 由 OpenRouter 在伺服器端執行搜尋後讓模型生成回覆,回應仍是純文字,呼叫與處理方式與一般請求完全相同。
  • tools 內容原樣轉發給 OpenRouter,平台不另行驗證;格式 / 可用工具型別以 OpenRouter 官方文件為準,傳錯會由 OpenRouter 回對應錯誤。
  • 啟用 web search 會由 OpenRouter 額外計費,費用一併反映在用量統計中。

多輪對話(messages)與生成參數

自 v2.1.2 起,除了單輪的 text / images / files,也可以直接帶 OpenAI 風格的 messages 陣列——自行組 system prompt、多輪對話歷史與角色設定,適合對話記憶、客服機器人等進階串接;並可搭配三個生成參數控制回覆行為。

messages 使用規則

  • 擇一使用:messages 與 text / images / files 互斥,同時帶回 400;messages: [](空陣列)也回 400。
  • role 白名單:每則訊息的 role 只接受 system / user / assistant(tool 角色尚未開放)。
  • content 兩種寫法:純文字字串;或 parts 陣列——型別只接受 text / image_url / file(能力與單輪模式相同,影片同樣不支援)。
  • 則數不設上限:以所選模型的 context window 為自然上限(全部訊息都計入 token),超過由模型端回錯誤。
  • tools(如 web search)兩種模式皆可搭配;回應格式不變,仍為統一格式的純文字 data。
  • 對話歷史由呼叫端自行保存與帶入,平台不儲存 session;messages 內容會原樣寫入用量紀錄供稽核(檔案僅記檔名),請勿夾帶敏感個資。

多輪對話 Request 範例:

JSON
{
  "model": "google/gemini-2.5-flash",
  "messages": [
    { "role": "system", "content": "你是客服助理,回答一律使用繁體中文。" },
    { "role": "user", "content": "上次說到哪?" },
    { "role": "assistant", "content": "說到出貨進度。" },
    { "role": "user", "content": [
      { "type": "text", "text": "看一下這張圖與檔案,幫我確認狀態" },
      { "type": "image_url", "image_url": { "url": "data:image/png;base64,iVBORw0KGgo..." } },
      { "type": "file", "file": { "filename": "出貨單.pdf", "file_data": "data:application/pdf;base64,JVBERi0..." } }
    ] }
  ]
}

生成參數(單輪與 messages 模式皆可帶)

參數值域用途
temperature0 – 2控制隨機性:偏低(如 0.2)適合抽取 / 分類等要穩定的任務;偏高適合創意生成
max_tokens≥ 1限制回覆長度上限,控制成本與回覆篇幅
response_formatjson_object / json_schema{"type":"json_object"} 讓回覆保證為合法 JSON 字串(prompt 中請同時明確要求輸出 JSON);{"type":"json_schema","json_schema":{...}} 可進一步指定結構
JSON
{
  "model": "google/gemini-2.5-flash",
  "text": "抽取:『7/20 前交付 100 件到台中廠』的日期、數量、地點,以 JSON 回覆(鍵:date, qty, location)",
  "temperature": 0.2,
  "max_tokens": 256,
  "response_format": { "type": "json_object" }
}
  • 三個參數未帶就不會送給模型,一律走模型預設值;超出值域(如 temperature: 2.5)回 400。
  • 其餘 OpenAI 生成參數(top_p / stop / frequency_penalty 等)不開放,帶了會被拒收,請勿嘗試。
  • 有帶的生成參數會一併寫入用量紀錄,方便事後追溯呼叫條件。

Response 格式

所有回應皆包在統一格式中:

JSON (success)
{
  "success": true,
  "code": 200,
  "data": "模型回答的文字內容...",
  "detail": "success"
}

失敗回應:

JSON (failure)
{
  "success": false,
  "code": 403,
  "data": null,
  "detail": "model_forbidden"
}
  • success:布林,程式判斷成功失敗。
  • code:對應 HTTP status。
  • data:成功時為模型回答的純文字字串(已剝除 id / usage / provider 等內部欄位)。
  • detail:成功固定為 "success";失敗為錯誤碼或中文描述。

Python (httpx)

python
import httpx

API_URL = "https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/model/chat"
SDK_KEY = "ordsk_xxxxxxxxxxxx_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
USER_TOKEN = "<admin 發放的 User Token>"
PROJECT_CODE = "<admin 後台「專案管理」頁複製的代碼>"

def chat(model: str, text: str) -> dict:
    resp = httpx.post(
        API_URL,
        headers={
            "X-SDK-Key": SDK_KEY,
            "X-User-Token": USER_TOKEN,
            "X-Project-Code": PROJECT_CODE,
            "Content-Type": "application/json",
        },
        json={"model": model, "text": text},
        timeout=60,
    )
    resp.raise_for_status()
    body = resp.json()
    if not body["success"]:
        raise RuntimeError(f"{body['code']} {body['detail']}")
    return body["data"]

if __name__ == "__main__":
    answer = chat("google/gemini-2.5-flash", "用一句話介紹台灣")
    print(answer)

python
import httpx

API_URL = "https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/model/chat"
SDK_KEY = "ordsk_xxxxxxxxxxxx_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
USER_TOKEN = "<admin 發放的 User Token>"
PROJECT_CODE = "<admin 後台「專案管理」頁複製的代碼>"

def chat_messages(model: str, messages: list[dict], temperature: float | None = None) -> str:
    payload = {"model": model, "messages": messages}
    if temperature is not None:      # 未帶就不放進 body,走模型預設
        payload["temperature"] = temperature
    resp = httpx.post(
        API_URL,
        headers={
            "X-SDK-Key": SDK_KEY,
            "X-User-Token": USER_TOKEN,
            "X-Project-Code": PROJECT_CODE,
            "Content-Type": "application/json",
        },
        json=payload,
        timeout=60,
    )
    resp.raise_for_status()
    body = resp.json()
    if not body["success"]:
        raise RuntimeError(f"{body['code']} {body['detail']}")
    return body["data"]

if __name__ == "__main__":
    history = [
        {"role": "system", "content": "你是客服助理,回答一律使用繁體中文。"},
        {"role": "user", "content": "我上週訂的貨到哪了?"},
        {"role": "assistant", "content": "請提供訂單編號,我幫您查詢。"},
        {"role": "user", "content": "訂單編號是 A12345"},
    ]
    answer = chat_messages("google/gemini-2.5-flash", history, temperature=0.3)
    print(answer)
    # 下一輪:把模型回覆 append 回 history 再呼叫,即可延續對話

串流回應(SSE)

若希望像 ChatGPT 一樣逐字即時顯示回應(而非等整段生成完才一次回),可改用串流端點。回應以 SSE(Server-Sent Events) 一段一段傳回,每段只含 id 與該段文字 content。

HTTP
POST https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/model/chat/stream
Content-Type: application/json
X-SDK-Key: <SDK Key 明文>
X-User-Token: <User Token 明文>
X-Project-Code: <專案代碼>
  • Header 與 Request Body 與 /model/chat 完全相同(model / text / images / files / tools,v2.1.2 起亦含 messages 多輪與 temperature / max_tokens / response_format 生成參數);不需額外帶 stream 欄位,端點本身即代表串流。
  • 回應 Content-Type 為 text/event-stream,不套用統一 { success, code, data, detail } 包裝;每筆事件為精簡的 data: {"id":"...","content":"..."},最後以 data: [DONE] 收尾。文字內容位於 content;OpenRouter 的 provider / cost / usage 等內部欄位不會外露。
  • 開串流前的錯誤(憑證 / 白名單 / 速率限制等)仍以一般 HTTP 4xx/5xx + { success:false, … } JSON 回絕,不會進入串流;因此程式應先檢查回應的 Content-Type / 狀態碼再決定是否逐塊讀取。
  • 本端點僅支援 OpenRouter 模型;internal 模型呼叫此端點會回 400 feature_not_supported。

把每筆 data: 的 content 依序串接,即為完整回答,遇 data: [DONE] 結束;id 為本次生成識別碼(每段相同,可用於回報問題)。token 用量只記在後台,不隨串流回傳。

Python (httpx 串流)

python
import json
import httpx

API_URL = "https://df-it-openrouter-dispatch-api.it.zerozero.tw/api/v1/model/chat/stream"
SDK_KEY = "ordsk_xxxxxxxxxxxx_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
USER_TOKEN = "<admin 發放的 User Token>"
PROJECT_CODE = "<admin 後台「專案管理」頁複製的代碼>"

def chat_stream(model: str, text: str):
    headers = {
        "X-SDK-Key": SDK_KEY,
        "X-User-Token": USER_TOKEN,
        "X-Project-Code": PROJECT_CODE,
        "Content-Type": "application/json",
    }
    with httpx.stream(
        "POST", API_URL, headers=headers,
        json={"model": model, "text": text}, timeout=None,
    ) as resp:
        # 開串流前的錯誤仍是一般 JSON,先擋下來
        if "text/event-stream" not in resp.headers.get("content-type", ""):
            body = resp.read().decode()
            raise RuntimeError(f"{resp.status_code} {body}")
        for line in resp.iter_lines():
            if not line.startswith("data:"):
                continue                      # 略過空行 / keep-alive 註解
            data = line[len("data:"):].strip()
            if data == "[DONE]":
                break
            chunk = json.loads(data)
            if "error" in chunk:               # 簡化格式:{"id":..,"content":..}
                raise RuntimeError(chunk["error"])
            print(chunk.get("content", ""), end="", flush=True)   # 逐字輸出
    print()

if __name__ == "__main__":
    chat_stream("google/gemini-2.5-flash", "用三句話介紹台灣")

適合聊天介面 / 長文生成等「有人即時在看」的情境;若只是後端批次處理或要拿完整結果再用,直接用 /model/chat 即可,不需串流。

測試怎麼確認串流正常運作
  • 挑可用模型:先 GET /api/v1/allowed/models(免憑證)從 data[] 取一個 model_key;串流僅支援 OpenRouter 模型。
  • 串流成功:用上方 curl -N 應看到「逐段 data: {"id":...,"content":...} → 最後 data: [DONE]」逐字浮現;若整段一次才出現,多半是中間 proxy 緩衝,非平台行為。
  • 驗開串流前錯誤:故意把 model 填一個不在白名單的值,應回一般 JSON {"success":false,"detail":"model_forbidden"}(而非 SSE)—— 這證明憑證 / 白名單等錯誤會在開串流前以標準格式回絕。
  • 對照非串流:同樣參數打 /model/chat 應回 {"success":true,"data":"…整段文字…"},可用來區分「是串流問題還是基本鏈路問題」。
  • 用量稽核:串流結束後,後台「用量紀錄」會新增一筆(含完整輸出文字與 token usage);呼叫端中途斷線則記為錯誤但保留已收到的部分內容。

查看部門用量紀錄(平台網站)

呼叫代理端點不需要登入本網站(見上文)。但自 v2.1.1 起,有所屬部門的使用者可另外登入平台網站,查看自己部門的用量紀錄——用量本質上是部門的成本,開放給部門成員自助掌握花費。

  • 誰看得到:登入後,若你有所屬部門,左側選單會出現「用量紀錄」;沒有所屬部門的帳號不會看到此功能(選單不顯示)。你只會看到自己部門的紀錄,看不到其他部門。
  • 看得到什麼:每一筆呼叫都是一列,可看到時間、模型、token 用量、花費、是否成功等;點單筆可展開單筆明細。

用量列表顯示所屬專案 + 專案篩選

  • 列表新增「專案」欄,一眼看出每筆呼叫屬於哪個專案(對應呼叫時帶的 X-Project-Code)。
  • 上方篩選列新增可輸入搜尋的「專案」下拉:輸入專案名稱關鍵字挑選後,列表只顯示該專案的用量,方便單獨檢視某專案的花費。

下載 Excel 更完整

在用量儀表板點「下載 Excel」,匯出的活頁簿包含更完整的多張工作表,讓你從不同角度盤點花費:

  • 總覽、部門、專案、專案 × 模型花費明細、依模型、使用者、時序。
  • 其中「專案 × 模型花費明細」可看到每個專案的花費再依模型拆解,快速掌握哪個專案、用哪個模型花得多。

管理員的操作與檢視範圍不變;非管理員檢視單筆用量明細時,不會顯示「AI 分析」區塊。

安全注意事項

  • 不要把 SDK Key / User Token 寫死於前端(Browser / App)或 commit 到任何 git repo;只能存於後端服務、CI Secret、或加密的設定管理工具。
  • 若懷疑憑證外洩,立即聯絡管理員撤銷:User Token 撤銷後對應使用者所有舊 token 立即失效;SDK Key 撤銷後對應部門所有呼叫立即失效。
  • 所有呼叫都會記錄一筆 usage_logs(模型、token、耗時、是否成功);管理員可在後台用量紀錄頁面查詢。
  • 本平台不會儲存 OpenRouter 回傳的內部 metadata;但會保留請求內容(含 base64 圖片)以利稽核,請不要在 prompt 中夾帶敏感個資。
